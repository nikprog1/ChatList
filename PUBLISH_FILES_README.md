# 📦 Файлы для публикации ChatList

Этот документ описывает все подготовленные файлы для публикации приложения на GitHub.

## 📋 Основные инструкции

### 1. **GITHUB_RELEASE_GUIDE.md**
   - **Назначение**: Подробная пошаговая инструкция по публикации релиза
   - **Содержит**: Все шаги от подготовки до публикации на GitHub Release
   - **Когда использовать**: При первом релизе или если нужна детальная инструкция

### 2. **QUICK_START_PUBLISH.md**
   - **Назначение**: Быстрая инструкция для опытных пользователей
   - **Содержит**: 5 основных шагов для быстрой публикации
   - **Когда использовать**: Для быстрых релизов, когда процесс уже знаком

### 3. **PUBLISH_CHECKLIST.md**
   - **Назначение**: Чеклист перед публикацией
   - **Содержит**: Список задач с чекбоксами для проверки перед релизом
   - **Когда использовать**: Перед каждым релизом для проверки готовности

## 📝 Шаблоны и документация

### 4. **CHANGELOG.md**
   - **Назначение**: История изменений проекта
   - **Содержит**: Все версии с описанием изменений
   - **Когда использовать**: Обновлять при каждом релизе с новыми изменениями
   - **Формат**: Следует стандарту [Keep a Changelog](https://keepachangelog.com/)

### 5. **RELEASE_NOTES_TEMPLATE.md**
   - **Назначение**: Шаблон описания для GitHub Release
   - **Содержит**: Готовый текст для вставки в описание релиза
   - **Когда использовать**: Копировать в описание при создании Release на GitHub
   - **Важно**: Обновить версию и ссылки перед использованием

## 🌐 GitHub Pages (лендинг)

### 6. **docs/index.html**
   - **Назначение**: HTML-лендинг для GitHub Pages
   - **Содержит**: Красивую главную страницу с описанием приложения
   - **Особенности**:
     - Адаптивный дизайн (работает на мобильных)
     - Современный градиентный дизайн
     - Кнопки для скачивания
     - Описание функций
     - Системные требования
   - **Когда использовать**: Автоматически публикуется на GitHub Pages
   - **Важно**: Обновить ссылки на репозиторий перед использованием

### 7. **docs/README.md**
   - **Назначение**: Инструкция по настройке GitHub Pages
   - **Содержит**: Как настроить и обновить лендинг

## 🤖 GitHub Actions (автоматизация)

### 8. **.github/workflows/release.yml**
   - **Назначение**: Автоматическая сборка и публикация релиза
   - **Что делает**:
     - Запускается при создании тега версии (v*)
     - Собирает EXE файл
     - Создает Release на GitHub
     - Загружает EXE в Release
   - **Когда использовать**: Автоматически при создании тега
   - **Требования**: Настроенные секреты GitHub (обычно уже есть)

### 9. **.github/workflows/pages.yml**
   - **Назначение**: Автоматическое развертывание GitHub Pages
   - **Что делает**:
     - Запускается при изменении файлов в `docs/`
     - Автоматически публикует обновления на GitHub Pages
   - **Когда использовать**: Автоматически при коммите в `docs/`

## 🚀 Быстрый старт

1. **Перед первым релизом**:
   - Прочитайте `GITHUB_RELEASE_GUIDE.md`
   - Обновите ссылки в `docs/index.html`
   - Настройте GitHub Pages (Settings → Pages)

2. **При каждом релизе**:
   - Обновите версию в `version.py`
   - Обновите `CHANGELOG.md`
   - Используйте `PUBLISH_CHECKLIST.md` для проверки
   - Создайте тег и Release (или используйте GitHub Actions)

3. **Обновление лендинга**:
   - Отредактируйте `docs/index.html`
   - Закоммитьте изменения
   - GitHub Pages обновится автоматически

## 📝 Важные замечания

### Ссылки в файлах

Перед использованием обновите следующие ссылки:
- В `docs/index.html`: замените `yourusername/chatlist` на ваш репозиторий
- В `RELEASE_NOTES_TEMPLATE.md`: обновите ссылки на репозиторий
- В `.github/workflows/release.yml`: проверьте правильность путей

### Версии

- Версия берется из `version.py`
- Обновляйте версию перед каждым релизом
- Используйте [Semantic Versioning](https://semver.org/)

### GitHub Pages

- Настройте в Settings → Pages
- Выберите source: branch `main`, folder `/docs`
- Сайт будет доступен через несколько минут после настройки

## 🔄 Процесс релиза (кратко)

```
1. Обновить version.py
2. Обновить CHANGELOG.md
3. Собрать EXE (pyinstaller)
4. Создать тег (git tag -a v1.0.0)
5. Создать Release на GitHub
6. Загрузить EXE в Release
7. (Опционально) Обновить docs/index.html
```
